# Changelog

## 1.0.0

- Added Git provider OAuth integrations (`app/git_oauth.py`, `app/git_routes.py`): GitHub and Gitee authorization-code flows with per-provider authorize URLs, token exchange, profile fetch and paginated repository listing; all provider calls go through one httpx client with sanitized, user-safe error messages.
- Added OAuth state management: single-use CSRF `state` rows (`oauth_states` table) bound to the starting user, consumed atomically on callback and expired after 10 minutes; consumed/expired states older than an hour are cleaned up on each new authorization.
- Added encrypted provider-token storage (`git_connections` table): access tokens are encrypted at rest with a stdlib-only scheme (per-record salt → domain-separated HMAC-SHA256 subkeys, HMAC-CTR keystream, encrypt-then-MAC 16-byte tag; no new crypto dependency) under `OAUTH_ENCRYPTION_KEY` (falls back to `AUTH_SECRET`). Tokens are never returned by any API, never logged, and deleting the row revokes the local grant; rotation of the key surfaces as a clear "disconnect and re-authorize" 400 rather than silent failure.
- Added private repository sync: `clone_and_scan` accepts an access token and builds authenticated clone URLs (GitHub `x-access-token`, Gitee `oauth2`); the sync endpoint attaches the stored connection token automatically, and git error output is redacted (`redact_secrets`) so tokens cannot leak through clone failure messages.
- Added explicit repository permission selection: `GET /api/git/{provider}/repos` lists what the token can see (visibility filter all/public/private) but persists nothing — only repositories the user clicks "同步" on enter the database.
- Added `Repository.is_private` (provider-side visibility metadata, persisted via migration 0008) distinct from `is_public` (portfolio exposure): private repos stay out of the public portfolio unless explicitly toggled.
- Added five Git integration endpoints, all user-scoped: `GET /api/git/providers` (configured/connected status + login + scopes), `POST /api/git/{provider}/authorize` (returns the provider authorize URL + state), `POST /api/git/callback` (code/state exchange, upserts the connection), `DELETE /api/git/{provider}` (disconnect, deletes the token row), `GET /api/git/{provider}/repos` (token-scoped repository listing).
- Added the frontend Git provider panel on the Projects page: per-provider configured/connected badges, "绑定授权" (redirects to the provider), "选择仓库同步" (repo picker with 全部/公开/私有 filters, private badges and one-click sync that fills provider/branch/is_private automatically), "断开" (disconnect), plus a manual-sync "私有仓库" checkbox and a `· 私有` marker in the repository rail.
- Added the OAuth callback route (`/oauth/callback`): new `OAuthCallbackPage` reads code/state (or provider error) from the URL, exchanges them through the backend, shows bound-account confirmation, and returns to the Projects page; App routing also covers the portfolio-style path-based branch.
- Added tenant isolation for Git data: `GitConnection`, `OAuthState` and `Repository` rows are all user-scoped; cross-user state callbacks and connections return 400/404, covered by tests.
- Added pytest coverage for Git OAuth (24 tests): token encrypt/decrypt roundtrip (no plaintext in blob, tamper detection, wrong-key failure), authorize-URL/state lifecycle (unknown provider 404, unconfigured 400), callback validation (unknown/expired/reused state, cross-user state rejection, re-authorize upsert), provider repo listing shape, connection status after connect/disconnect, sync passing the connection token and persisting `is_private`, undecryptable-token 400, and token redaction in git clone errors — bringing the suite to 119 tests.

- Added interview playgrounds (`runner/main.py`, `app/playground.py`, `app/playground_routes.py`): SQL, Redis and FastAPI sandboxes for hands-on practice, backed by dedicated `sandbox-db` / `sandbox-redis` services on the internal-only network — never the main database or main Redis.
- Added sandbox session isolation: `playground_sessions` rows (Alembic 0009) carry an unguessable 32-hex `session_key` that the runner resolves into a per-session PostgreSQL schema (`s_<key16>`, marker table with idle timestamps, search_path set per connection) or a per-session Redis database index (deterministic blake2b hash + linear probe, marker key with 2h TTL, stale databases flushed before claiming). Cross-session data pollution is impossible by construction; expired sessions 410 and are lazily deleted after an hour.
- Added double-sided dangerous-input interception: the backend (`app/playground.py`) and the runner compile the identical `SQL_DENY_RE` / `REDIS_DENY_COMMANDS` (parity-tested — edit both together). SQL literals, quoted identifiers, comments and dollar-quoted blocks are blanked before matching (so `VALUES ('drop database joke')` is fine) and session-control verbs (SET / BEGIN / VACUUM / …) are only denied at statement start (so `UPDATE t SET …` is fine). SQL batches run as one implicit transaction with a 5s statement timeout and capped result sets (200 rows / 50 columns / 200-char cells); Redis arguments travel as separate protocol parameters so a command can never inject a second one.
- Added five playground endpoints: `GET /api/playground/meta` (public: kinds, limits, policy, samples), `POST /api/playground/sessions` (create sql/redis session), `POST /api/playground/sql`, `POST /api/playground/redis`, `POST /api/playground/fastapi` (stateless — user app runs in the same `-I` subprocess isolation as `/run` with a 6s timeout and one request served through `httpx.ASGITransport` on a single thread) and `POST /api/playground/reset` (wipe the session's schema/database).
